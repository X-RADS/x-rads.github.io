# X RADS 双语临床查阅网站 Demo 设计

## 1 项目目标

X-RADS 第一阶段面向医学影像科医生，提供 RADS 的中文和英文查阅与汇总功能。

首个 Demo 用于验证三件事：

1. 医生能否通过名称、器官、疾病或影像模态快速找到 RADS。
2. 中文详情页能否在符合中文阅读习惯的同时保留英文全称、原始分级和关键术语。
3. 结构化内容是否便于后续补充更多 RADS、版本记录和评分工具。

Demo 不包含账号、病例上传、患者数据、数据库、后台管理、在线协作和正式临床决策支持。

## 2 发布与仓库方案

首期使用一个公开仓库：`X-RADS/x-rads.github.io`。

网站使用 GitHub Pages 发布到 `https://x-rads.github.io/`。公开仓库中只存放网站代码、结构化条目、自制或已授权图片、参考文献元数据和维护说明。

`Materials` 中的投稿文稿、原始 PDF 和其他可能受版权限制的全文材料不进入公开仓库。网站只展示自行整理的摘要、必要的短术语、书目信息以及官方来源链接。

## 3 Demo 技术方案

为尽快看到效果，Demo 采用原生 HTML、CSS 和 JavaScript，不引入前端框架、数据库或构建工具。

内容存储为静态 JSON。浏览器负责搜索、筛选、语言切换和页面渲染。该方案可以直接由 GitHub Pages 托管，初期没有服务器费用。

当内容规模、贡献者数量或评分工具复杂度明显增加时，再评估迁移到 Astro 等静态站点生成器。Demo 阶段不提前增加这类复杂度。

## 4 页面与使用路径

### 4.1 首页

首页采用已确认的混合入口方案：

- 顶部提供关键词搜索。
- 提供按人体解剖部位浏览入口。
- 提供影像模态和发布状态筛选。
- 展示常用 RADS 和最近更新。
- 右上角提供中文和英文切换。

默认进入中文界面。语言切换后保留当前查询、筛选条件和正在查看的 RADS。

### 4.2 RADS 列表

列表卡片展示：

- RADS 简称。
- 中文名称或英文名称。
- 器官或应用领域。
- 影像模态。
- 发布或开发状态。
- 当前收录版本。

Demo 支持关键词、解剖部位、影像模态和状态的组合筛选。

### 4.3 RADS 详情页

详情页采用已确认的临床速查结构，信息顺序如下：

1. 中文名称、英文全称和简称。
2. 发布或认证机构、当前状态与版本。
3. 适用领域、影像模态、分级范围和临床目的。
4. 中文临床概览。
5. 评分或分类表，保留原始英文术语并提供中文解释。
6. 关键术语与适用条件。
7. 版本记录和上次核对日期。
8. 官方页面、指南、DOI 或 PubMed 链接。
9. 相关 RADS。
10. 专业查阅与教学用途声明。

## 5 双语策略

中文界面以中文阅读习惯为主，不进行机械逐句翻译。

- 名称首先显示中文，随后显示英文全称和简称。
- 分级标签、序列名称、缩写和官方术语保留原文。
- 中文字段解释术语的临床含义和使用条件。
- 英文界面使用相同的事实字段，另行维护英文摘要和说明。
- 版本号、DOI、PMID、URL、分级代码和机构名称使用共享数据，避免两种语言出现事实不一致。

## 6 数据模型

每个 RADS 条目至少包含：

- 稳定标识和简称。
- 中文名称与英文全称。
- 中文摘要与英文摘要。
- 开发或认证机构。
- 发布状态。
- 解剖部位和应用领域。
- 影像模态。
- 当前版本和发布日期。
- 评分或分类项目。
- 原始术语与中文解释。
- 官方来源、DOI、PMID 和参考文献。
- 上次人工核对日期。
- 相关 RADS。

Demo 首批录入 BI-RADS、LI-RADS、Lung-RADS、O-RADS、PI-RADS 和 TI-RADS，用于覆盖不同器官和模态。内容以 `Materials/RADS_诊断学_20251228-XY.docx` 为初始索引，再逐项核对官方来源。

## 7 数据维护流程

1. 新增或更新条目前，先确认官方来源和版本日期。
2. 修改结构化 JSON 和参考文献记录。
3. 在本地执行格式与链接检查。
4. 通过 GitHub Pull Request 审核后合并。
5. 合并后由 GitHub Pages 自动发布。
6. 条目显示最后核对日期，并保留更新记录。

初期由项目维护者审核全部内容。外部贡献者可通过 GitHub Issue 提交新增线索或纠错，不直接修改临床内容。

## 8 风险与边界

- 网站不替代官方指南或所在机构规范。
- Demo 不处理患者数据，不允许上传影像或报告。
- 不复制无授权的指南全文、期刊插图或量表版式。
- 对处于开发中、非官方认证或证据有限的 RADS 明确标注状态。
- 数据缺失时显示“尚未核对”，不根据常识自动补齐。
- 外部链接失效时保留文献标识，并在维护检查中报告。

## 9 验证标准

Demo 完成时应满足：

- 桌面和手机浏览器均可使用。
- 中文和英文界面均可访问。
- 搜索与全部筛选组合可正常工作。
- 六个示例 RADS 可进入详情页。
- 中文详情保留英文全称、原始分级和原始术语。
- 语言切换不丢失当前页面上下文。
- 页面不请求或存储患者信息。
- 可作为静态文件直接发布到 GitHub Pages。

## 10 后续阶段

Demo 验证后再依次扩展：

1. 补齐现有材料中的全部 RADS。
2. 增加版本比较和更新时间线。
3. 增加基于官方规则的评分辅助工具。
4. 增加结构化报告模板和可下载表格。
5. 根据使用量决定是否需要独立数据仓库、内容管理系统或后端服务。
